# 已確認的口試申請流程決策

本頁記錄與使用者逐步核對後的**正式流程方向**，是流程決策的唯一權威。它不表示程式已全部實作；實作進度見 實作計畫。較早的工作設計稿若有不同假設，以本頁為準。歷次修訂見文末「修訂紀錄」。

目前以**本系**的規定為準；其他系所規定不同之處（例如 Portal 委員欄非必填）日後再擴充。

## 端到端流程（2026-09-23 版）

```text
學生在 Portal 正式申請（本系統不介入）
系辦設定本期學期＋填寫截止日後，學生端才開放填寫
學生在本系統填附件 3 補充資料（可暫存），填寫截止日（含）前可反覆修改（系統不催）
系統每天建預覽版主檔供儀表板檢視（不寄信）
        │
系辦下載附件2 並上傳（可在填寫截止日前提早上傳；資料有誤可整份重傳）→ 全收、不篩審核狀態
正式檢核開始日＝max(填寫截止日隔天, 附件2 第一次上傳隔天)，當天起：
          → 以學期＋學號配對學生填寫 → 建主檔（套用專員修正）→ 自動檢核
          → 學生責任問題直接寄補件信（不經系辦）；其餘分流給系辦／專員
        │
補件期間 ── 補件截止前每日催未補者；學生重送 → 自動重檢
人工關卡：專員審核口試委員資格與各項例外 → 每案按「已處理」放行
        │  （人工關卡在補件截止日之前進行；放行後委員名單變動即撤銷放行）
        ├→ 學生資料齊全即寄附件4 給全部指導教授參考（不等放行、不用回信；教授要求修改由信箱 agent 擬修改、專員核准）
        └→ 向新口委／撥帳資料不齊者寄信索取個資 → 回填直接寫入口委資料庫（不催）
補件截止日＝正式檢核開始日＋補件天數：硬截止，鎖住學生輸入、停止催件、凍結本輪結果
        │  （逾期未完成案件由專員個案處理）
口試前 N 天委員仍未交個資 → 例外
口試後：附件6（交付版個資留白）簽收回收，現場手寫個資由專員登錄
學期切換：舊學期封存，未結案件由系辦線下處理
```

主檔是唯一資料權威。任何來源（附件2、學生填寫、系辦參照檔、委員回填）更新後，都先重建或重檢主檔，再由主檔產生文件；不直接修改附件，也不把人工改過的附件回灌系統。專員需要手動更正資料時，在系統案件頁修改，存成**專員修正層**（見第四節第 6 條），不直接改來源或附件。

## 一、資料來源與分工

1. 學生端資料來源只有兩個：**Portal** 與**本系統學生介面**，不會有第三個入口。
2. 學生一律先在 Portal 正式申請。系辦下載附件2（Portal 匯出，系所審核名單－委員資料）上傳本系統，不分批匯入。以無 API 為前提設計。
   - **可以提早上傳**：在填寫截止日之前上傳也可以，系辦能先在總覽看到誰還沒填，但截止前一樣不寄信（2026-10-01）。
   - **可以整份重傳**：附件2 有誤時，系辦重新上傳正確的檔案，整份取代舊檔，重建主檔並重新檢核。補件截止日以**第一次**上傳計算，重傳不會重算。重傳後新出現的學生照常檢核、寄補件信，總覽標示「補件時間較短」；新檔裡消失的學生如果已寄過補件信，不自動刪除，列為例外交專員確認（2026-10-01）。
3. 附件2 是**唯一的案件來源**。匯入時全部收入，不依「審核狀態」篩選，也不在匯入時人工介入。**能進入本系統的學生皆確定要口試**，系統不設「案件是否成立／正式簽核是否通過」的判定關卡。
4. 本系統學生介面只收 **Portal 沒有的資料（附件 3）**，不收 Portal 已有的欄位；學期、學號由登入身分帶入。學生不能在本系統建立 Portal 不存在的案件。
5. 截止日匯入附件2 後，以**學期＋學號**配對學生填寫；配不上的填寫列為例外交專員處理。
6. 系辦上傳檔（見第九節）只作為對照與計算依據，不是另一個案件入口。
7. 附件2 的資料問題（缺欄位、重複委員、同案欄位不一致）一律逐案列為例外交專員，**不讓一筆 Portal 資料擋住整批建檔**。同一學生有多筆 Portal 紀錄（申請、考試委員異動、撤銷）時，以**簽核完成時間最新**的紀錄為目前狀態，並標給專員確認（真實匯出的呈現方式仍待確認，見第十節）。

## 二、學生填寫

1. 表單欄位：學生 Email、口試日期、起訖時間、地點、口試方式（實體／視訊／部分視訊）、指導教授與其 E-mail（可多位，共同指導；E-mail 必填，2026-09-23 追加）、口試委員名單（姓名、服務單位、職稱、E-mail、是否視訊出席）、論文題目（選填；若 Portal 匯出有題目，以 Portal 為準）。欄位內容先全列，之後再刪減。
2. **口試委員名單與每位委員的 E-mail 皆必填**（以本系為準）。即使 Portal 已有委員名單，學生仍在本系統填一次；兩邊名單不一致時列為例外，以附件2 為準。比對時在**同一案件內以姓名**對應（去掉「教授／博士／老師」等稱謂），同名時才以服務單位區分，服務單位寫法不同不視為不一致。
3. 學生**不填**委員的身分證、銀行、帳號、戶籍地址；委員個資不經學生（見第五節）。
4. 口試委員與口試時間由指導教授決定，學生本來就知道自己的委員；系統不另設確認步驟。委員是學生自行填入，不是從選項挑選。
5. **不需系辦審核**：學生送出即為有效版本，直接作為主檔輸入。填寫截止日前可自由修改；重填時載入上一版完整資料，送出完整快照，系統建立新版本並歸檔舊版。
6. 學生如何進入本系統（Portal SSO、校務 Email 專屬連結或其他）**暫緩決定**，等 Portal 端能力確定後再定；新流程與介面不得依賴任一方案。現有「輸入學號登入」僅為開發原型，正式實作時登入驗證與案件查詢要分開，讓入口可替換。
7. **送出時即檢查**：學生 Email 與委員 E-mail 格式、至少一位指導教授及其 E-mail、委員至少 3 位（博士 5 位在附件2 帶入學位別後檢查）、委員服務單位、口試日期。不通過就不儲存，也不歸檔舊版。送出後另顯示自我檢查提示（口試日期已過、早於流程可完成日、博士委員人數），只是提示，不是催件。
8. 系辦設好**本期學期**和**填寫截止日**之前，學生端只顯示「本學期尚未開放填寫」，不能送出；設定後，學生端固定使用該學期，學生不能自己填學期（2026-10-01）。
9. **暫存**：學生可以暫存一半的資料，之後回來接著填；暫存不算送出，也不做送出時的檢查。填寫截止時如果只有暫存、從未送出，視為「未填寫」，照常寄補件信要求送出，信中提醒有暫存可以接續。填寫期間不會因為「有暫存沒送出」寄信，只在學生頁顯示提示（2026-10-01）。

## 三、截止日、建檔與補件

1. **填寫截止日（含）前**：學生可自由修改；系統每天建預覽版主檔供儀表板檢視，**不寄任何信、不催件**（截止日前系統沒有附件2，不知道誰該填）。
2. **正式檢核開始日**＝max(填寫截止日隔天, 附件2 第一次上傳隔天)。從這天起，系統建主檔、自動檢核，學生責任的問題**直接寄補件信給學生**，不先經系辦，儀表板同步顯示。填寫截止日當天學生仍可修改，避免系統在學生修改中途寄信。
3. **補件期間**：只有本輪曾被標出學生責任問題（收到補件通知）的案件可修改；修好一項後，仍可在補件截止日前更正其他錯誤。學生重新送出完整表單即為補件完成證據，系統自動重檢；只有本輪檢核中問題確實消失才標為解決。不以學生自由文字回信改變案件狀態。
   - **補件時冒出新問題**：學生送出後，學生頁立即顯示新問題；隔天每日檢核時問題仍在，才寄一封補件信，只列新問題。截止日不變，同一個問題代碼不重複寄（2026-10-01）。
   - **沒收到補件信的學生要異動**（例如口試改期、委員換 E-mail）：資料保持鎖定。學生在學生頁按「**申請異動**」並填寫原因，申請會出現在專員介面；專員對單一案件按「**開放修改**」（須填處理人和原因），開放到補件截止日。學生直接寄信到系統的**專用業務信箱**時，由 LLM 分類並摘要後顯示給專員；LLM **不能自動解鎖**，寄件者對不上案件登記的學生信箱時標示「身分未驗證」（2026-10-01）。
4. **補件截止日**＝正式檢核開始日＋系辦設定的補件期限天數（2026-10-01 修正，原為「填寫截止日＋天數」，系辦晚傳附件2 時學生的補件時間會被壓縮）。系辦可以在設定頁**手動覆寫**補件截止日。每日自動化失敗、補件信晚寄時，截止日**不自動順延**，總覽警示「首次補件信晚了 N 天寄出」，由系辦決定要不要手動延後。
5. 補件截止日為**硬截止**：鎖住學生輸入、停止催件、做最後一次重檢並凍結本輪結果。凍結不代表資料完備；仍有問題的案件標為「**逾期未完成**」，停在放行之前，不得靜默混入文件，也不會自動放行。專員可以**個案處理**：自己在案件頁補資料（專員修正層）後放行，或對單一案件延長學生修改期限（須填處理人和原因）（2026-10-01）。
6. 補件信寫明補件截止日，不顯示內部問題代碼。學生沒有留 Email 時，依系辦設定的學生信箱後備格式寄出（未設定則不寄，系辦總覽標示「無信箱」）。
7. 系辦總覽在附件2 上傳後以附件2 案件為主，標示未填寫、無信箱、附件2 查無的填寫；並警示「尚未設定填寫截止日」「填寫截止後尚未上傳附件2」「每日自動化失敗」。
8. 網頁與每日自動化共用同一份目前主檔（`outputs/current/`），每次建檔另存當日快照。
9. 建檔失敗時保留先前主檔，不把舊主檔顯示為最新；保留錯誤並提供重試入口。連續送出、檔案更新或建檔失敗時，依目前有效資料重算，避免較舊結果覆蓋較新主檔。

## 四、問題分流、例外與人工關卡

1. 主檔建立後執行資料檢核，每個問題帶**問題代碼**、**責任標籤**（學生／系辦／口試後處理／不通知）與是否阻擋附件4、附件6。同一案件可有多筆不同責任的問題；避免把系辦檔案問題寄給學生，也避免無關問題擋住所有文件。
2. 學生責任：寄補件信 → 催件 → 學生重送 → 自動重檢。系辦責任：重新上傳正確資料 → 自動重檢；可自動驗證的問題不能只靠人工勾選結案。
3. **例外狀況**交專員處理，包括：學生填寫在附件2 查無案件、附件2 資料問題與多筆紀錄、附件2 與學生委員名單不一致、委員人數不足（碩 3／博 5，名單以附件2 為準故由專員處理）、委員職級不符、以姓名＋單位沿用舊口委、口試日期早於「補件截止日＋預留教授核對天數」、口試將至委員仍未交個資。
4. **委員職級規定**：碩士口試委員需助理教授以上，博士口試委員需副教授以上。不符時**不排除、不擋流程**，系統標出供專員參考；優先看附件2「委員資格」欄，職稱為輔助，無法判斷的職稱也標出。例外說明附上附件2「委員資格」原文，並分成「Portal 特殊資格」（系所已認定的特殊資格）與「職稱未達或無法判斷」兩類。
5. **人工關卡**：專員審核口試委員是否符合資格（例外多，必須人工判斷）並處理該案例外，按「**已處理**」放行。**每案一次**，在補件截止日之前進行。放行後才寄信向委員索取個資，文件中心手動產檔也只納入已放行案件（每日流程寄教授的附件4 不等放行，見第六節）。放行紀錄留存處理人（必填姓名）、時間與備註。放行、附件6 回收登錄、委員回填登錄、核准 AI 擬的修改等人工操作都須填處理人並寫入稽核。
   - 2026-10-01 確認維持**每案都要專員放行**，不改成「只有例外才停」：專員需要保留手動處理例外、處理自動流程做不到的事的空間（專員實際想手動做哪些事仍待確認，見第十節）。
   - **放行後委員名單變動就撤銷放行**：委員名單（姓名＋服務單位＋職稱）一變，案件就回到「待放行」；專員重新放行前，不寄新版附件4，也不向新委員索取個資。名單沒變、只多了其他例外的，維持放行，只標「放行後有新例外」提醒（2026-10-01）。
6. **專員修正層**（2026-10-01）：專員在案件頁修改欄位時，修正另外存成一層，不直接改附件2 或學生填寫。每次重建主檔都套用修正，所以重傳附件2、學生重新送出都不會蓋掉；檢核也照修正後的值做。來源後來改成跟原值、修正值都不同的第三個值時，列為例外交專員確認。每筆修正都記錄處理人、時間和原因，並寫入稽核。

## 五、委員個資

1. 委員個資（身分證、銀行、帳號、戶籍地址）只在**系統與委員本人之間**傳遞，不經學生。
2. 專員放行後，系統寄信給**舊口委資料庫查無此人**，或**有此人但撥帳資料不齊**的委員，向本人索取個資。資料庫已有完整資料者直接沿用，不需學生或委員確認。「資料庫已有此人」以身分證字號比對；新案件委員沒有身分證時，**姓名＋服務單位在資料庫中恰好一筆相符**即視為同一人沿用，並標示給專員在人工關卡確認（2026-09-23 確認）。
   - **本系委員**免撥帳資料，但舊口委資料庫查無此人時，系統只向他索取**身分證字號**（不要銀行資料），用來確認身分；否則暫定身分會一直擋住附件6（2026-10-01，全流程演練發現）。
3. 委員回填資料**直接寫入舊口委資料庫**，專員於人工關卡順便檢視。
4. 委員未回覆**不催件**（2026-10-01）：口試前 N 天（系辦設定，預設 3 天）仍未交個資就列為例外，由專員自行決定是否聯絡；口試當天仍未交的，在口試現場以附件6 補齊。
5. 回覆管道（2026-09-23 追加）：索取信附**每位委員專屬連結**，委員線上填寫（身分證驗檢查碼、身分證與帳號輸入兩次），送出後頁面不回顯個資；委員若改以回信提供，由系辦在「委員個資」頁登錄。連結需部署時設定對外網址，正式上線須使用 HTTPS；個資存檔加密仍日後處理。
6. 交通費依服務單位查距離表計算；**視訊口試交通費為 0**；部分視訊時，學生勾選「視訊出席」的委員交通費為 0。
7. **口試費上限**：依附件3 說明，審查碩士班學生一名 1000 元以 3 名為上限、博士班一名 2000 元以 6 名為上限。**已確認（2026-10-10）維持現行算法**：上限以「每位委員在同一清冊場次」計——同學期、同學位別、同一指導教授（共同指導以完整組合計）、同一口試日期為一個場次（`config.FEE_PAPER_CAP`＝碩 3／博 6）。
8. **本校他系委員**（2026-10-10 確認維持現值）：不比照本系，仍需撥帳資料、照算交通費（`config.HOME_UNIV_FEE_EXEMPT = False`）；只有本系委員免撥帳資料與交通費。
9. **指導教授兼任委員**（2026-10-10 確認維持現值）：照領口試費（`config.ADVISOR_EXAM_FEE_EXEMPT = False`）。

## 六、附件4（供指導教授參考）

## 八、期限與催件參數

1. 所有需要人上傳、補件、確認或回覆的關卡，都要有明確截止時刻及負責人；資料轉換、檢核、符合條件後的產檔等無需人判斷的動作盡量自動執行。
2. **催件日期由系辦在介面自行設定**，不寫死在程式。全系統一套，分組如下：
   - **學生**：本期學期、填寫截止日、補件期限天數、**補件截止前**幾天開始催未補者、學生信箱後備格式；每日發送時刻；曆日或工作日；**國定假日**（工作日計算時排除）。**填寫截止前不催**。
   - **教授（附件4）**：只有「預留教授核對天數」，用來提醒口試日期是否太早；教授不用回信，不設確認期限、不催（2026-10-12）。
   - **附件6 回收**：回收期限天數，從交付日與口試日較晚者起算，逾期提醒該場口試委員（2026-10-13）。
   - **委員（個資索取）**：不催件，只設「口試前幾天仍未交個資列例外」（預設 3 天）。
   - **補件截止日手動覆寫**：有值時取代公式算出的日期。
3. 每日最多催一次；同一天重跑不得重寄；已送出新版本的案件不再收到「尚未提交」催件。
4. **學期切換**（2026-10-01）：系辦把本期學期切到下學期之前，畫面先列出舊學期還有幾件沒結案（附件6 未收回等；不看教授是否回信），要系辦確認後才切換。切換後舊學期封存，只能查看，系統不再催繳或寄信，剩下的由系辦線下處理。
