# 提案型 agent 設計（2026-10-08）

原則：**AI 提案、專員決定**。三個 agent 都只把建議放進「AI 建議」頁（`/office/ai-proposals`）的佇列，專員按採用／改判／不採用之後才生效；專員確認的結果存下來，下次直接查表，不再呼叫模型。流程決策以 [已確認流程決策](已確認流程決策.md) 為準，LLM 使用範圍依 LLM 前置研究 第一節第 4、5 項與第二、三節。

## 共同機制

| 項目 | 做法 |
|---|---|
| 觸發 | 專員在「AI 建議」頁按「依目前主檔產生建議」，三個 agent 依序掃目前主檔 |
| 模型介面 | `koushi/llm.py`：`StructuredLLM.complete_json(system, user, schema_name=...)`；`make_llm()` 沒有 `GEMINI_API_KEY`／`OPENAI_API_KEY` 時回傳 `None`，只做規則比對 |
| 軌跡 | `koushi/agent_trace.py` 每一步（查表、規則檢查、呼叫模型、提案、專員決定）寫入 `audit_log.json`（`source="agent_trace"`），含工具、模型、提示詞版本、耗時、輸出；頁面每筆建議可展開「執行軌跡」 |
| 佇列 | `state/ai_proposals.json`；同一主題（單位、職稱、異常）已有建議或已決定就不重問模型；只有「模型失敗」的待決建議會在下一輪重試 |
| 錯誤 | 逐項捕捉例外、逾時、格式錯誤、超出候選的回答；該項標「模型失敗」留給專員，不影響其他項 |
| 開關 | `state/agent_settings.json`，三個 agent 各一個，預設開；**沒有任何自動套用選項** |
| 個資 | 送模型前組內容時就不放個資；`ai_proposals.scrub()` 再遮蔽身分證、Email、8 碼以上數字（帳號、電話）作最後防線 |
| 決定紀錄 | 每個決定都要填處理人，記時間、備註，寫稽核與軌跡 |

## A. 委員服務單位 → 距離表對應（交通費，高風險）

- **輸入**：主檔中交通費查不到距離的校外服務單位（依正規化寫法去重）。
- **步驟**：
  1. 已確認對照表有這個寫法 → 建檔時直接查表，不進佇列。
  2. 確定性候選檢索（`affiliation_agent.search`）：臺／台、國立／私立、學系／系／研究所、空白標點，加上縮寫種子表（台大／NTU、清大／NTHU、成大／NCKU、交大／NYCU、中研院、資工／CSIE 等），算相似度與同校判斷，取前 8 筆。
  3. 正規化後恰好一筆完全相同 → 規則提案（不呼叫模型）。
  4. 其餘請模型在候選中排序（提示詞 `affiliation-v1`），回 `{match_id 或 null, confidence, rationale}`；`match_id` 不在候選內視為無效。
- **送模型**：服務單位字串＋候選距離表單位名稱。不含委員姓名或任何個資。
- **輸出**：AI 建議（候選、分數與理由、信心、理由）。專員可採用、改指定任一距離表單位、或「不對應」（維持查無距離，請補距離表）。
- **快取**：`state/affiliation_aliases.json`，版本號遞增，每筆記處理人、時間、來源（採用 AI／專員改指定）、建議編號；有完整歷史，可在頁面撤銷。建檔時 `DistanceTable.aliases` 只讀這份已確認的對照，對照檔也列入來源指紋。
- **安全**：未確認前交通費維持 `None`、`NO_DISTANCE` 例外照列；建議本身從不碰金額。公里數與金額仍由距離表計算。

## B. 來源異常修正建議

- **輸入**：主檔 `source_issues` 中有案件鍵、責任為系辦的異常（附件2 同案欄位不一致、多筆紀錄、委員名單不一致、修正層衝突等）。沒有案件鍵的來源列無法套用專員修正層，仍在「來源異常處理」頁人工處理。
- **送模型**（提示詞 `correction-v1`）：問題代碼、欄位、說明（學生姓名、學號、案件鍵、委員姓名換成代號）、口試日期／時間／地點／方式／題目、委員代號＋服務單位＋職稱＋視訊出席。不送 Email、身分證、銀行、地址。
- **輸出**：`{action: correct|none, field, member_ref, new_value, rationale}`。只能改上述案件欄位與委員的職稱、服務單位、視訊出席；新值用專員修正層同一套檢核驗證，原值由程式從主檔讀，不採信模型。
- **套用**：**從不自動套用**。專員按「套用建議」或「改值後套用」才呼叫既有 `save_case_correction`，處理人、原因（含建議編號與理由）寫進修正層與稽核，下一次建主檔起生效。
- **快取**：同一異常（以異常內容雜湊）只問一次。

## C. 委員職稱／資格輔助判讀

- **輸入**：確定性規則（`validation._title_rank`）判斷不了、且附件2「委員資格」沒有註明「符合」的職稱（兼任、客座、英文、業界職稱等）。
- **送模型**（提示詞 `title-v1`）：只有職稱字串。
- **輸出**：教授級／副教授級／助理教授級／未達助理教授級／無法判斷，加理由。
- **決定**：專員確認或改判後存進 `state/title_levels.json`（快取，同一職稱不再問模型）。**只供參考**：不改變 `COMMITTEE_RANK_EXCEPTION`、不放行案件；委員資格最終仍由專員在人工關卡判斷（決策第四節第 4、5 條）。

## 不做的事

- 不讓模型決定金額、公里數、資格、放行或身分比對。
- 不把未確認的建議寫進主檔、修正層或對照表。
- 不提供「信心夠高就自動採用」的設定。
