# 部署與上線操作手冊

這份手冊說明怎麼把口試系統裝到一台 Windows 主機上正式運作：網頁、每日自動化、備份都在同一台。
上線前還沒解決的事項見 上線前待辦清單；本手冊只處理「環境怎麼架」。

```text
學生／系辦／委員的瀏覽器
        │ https://（對外網址，KOUSHI_PUBLIC_URL）
        ▼
HTTPS 反向代理（學校網管提供，或 IIS／Caddy）  ← 尚待決定，見第 9 節
        │ http://127.0.0.1:5000
        ▼
deploy\start-web.ps1（waitress） ─┐
deploy\run-automation.ps1（每天）─┼─ 讀寫同一份資料：resource\mockdata\、outputs\
deploy\backup_state.py（每天）  ──┘
```

## 1. 安裝

在主機上以系統管理員身分開 PowerShell，依序執行：

1. 安裝 Python 3.12（安裝時勾選 Add to PATH）。
2. 取得程式碼後，在專案資料夾建立虛擬環境並安裝套件：
   ```powershell
   python -m venv .venv
   .venv\Scripts\python.exe -m pip install -r requirements.txt
   ```
3. 安裝 [LibreOffice](https://www.libreoffice.org/)（附件4 官方範本是舊式 .doc，系統要靠它轉成 .docx）。
   裝在預設位置 `C:\Program Files\LibreOffice` 即可自動找到；裝在別處時在 `.env` 設 `KOUSHI_SOFFICE`。
4. 放正式範本（見第 3 節）。
5. 建立 `.env`（見第 2 節）。
6. 執行上線前自我檢查，直到沒有「缺」：
   ```powershell
   .venv\Scripts\python.exe deploy\preflight.py
   ```

## 2. 必設環境變數（`.env`）

把 `deploy\.env.example` 複製到專案根目錄、改名為 `.env`，填入實際值。`.env` 已在 `.gitignore`，不會被推上 GitHub。
網頁啟動腳本、每日自動化腳本都會自動讀這個檔。

| 名稱 | 必填 | 用途 |
| --- | --- | --- |
| `KOUSHI_WEB_SECRET_KEY` | 是 | 登入 session 的簽章金鑰。固定一組隨機字串，換掉會讓所有人被登出。產生：`python -c "import secrets; print(secrets.token_hex(32))"` |
| `KOUSHI_OFFICE_PASSWORD` | 是 | 系辦登入密碼（目前只有一組共用密碼） |
| `KOUSHI_PUBLIC_URL` | 是 | 系統對外網址，**必須是 `https://`**。委員專屬連結、信中連結都用它組出來；每日自動化寄信時也要用到 |
| `MAIL_SENDER` | 是 | 寄信用的 Gmail 帳號 |
| `MAIL_PASSWORD` | 是 | 該 Gmail 的「應用程式密碼」（16 碼，不是登入密碼；帳號需先開兩步驟驗證）。Gmail 還要開啟 IMAP，系統才能讀教授回信 |
| `MAIL_IMAP_HOST` | 否 | 不是 Gmail 時的 IMAP 主機 |
| `KOUSHI_SOFFICE` | 否 | LibreOffice 不在預設位置時，`soffice.com` 的完整路徑 |

## 3. 正式範本與 LibreOffice

系統依官方格式套版，範本要放在 `resource\template\`，**檔名必須完全一致**：

| 檔案 | 用途 | 需要 LibreOffice |
| --- | --- | --- |
| `resource\template\附件4-學位口試一覽.doc` | 寄給指導教授參考的學位口試一覽表（教授不用回信） | 是（.doc 要先轉 .docx） |
| `resource\template\附件6-學生口試費清冊.xlsx` | 口試後簽收回收的口試費清冊 | 否 |

- 範本是**空白的官方格式檔**，向系辦索取。不要拿填過真實資料的舊附件來當範本。
- `.gitignore` 會擋掉所有 Office 檔（`.doc/.docx/.xls/.xlsx/.csv`），這是刻意的個資防呆，**不要用 `git add -f` 硬加**。範本要另外交付（隨身碟、雲端硬碟），在每台機器上手動放進去。
- 放好之後執行下面的指令，原本因缺範本而失敗的 4 個測試應全部通過：
  ```powershell
  .venv\Scripts\python.exe -m pytest tests\test_application_generate.py tests\test_fee_rules.py -q
  ```
  這 4 個測試只用到附件6 範本。附件4 要實際產一次才驗得到（系辦工作台「文件中心」→「產生附件4」），失敗時畫面會顯示原因，最常見的是 LibreOffice 沒裝好。

## 4. 啟動網頁

```powershell
powershell -ExecutionPolicy Bypass -File deploy\start-web.ps1
```

- 用 waitress 啟動，預設只聽本機 `127.0.0.1:5000`，由前面的 HTTPS 反向代理轉進來。
- 少了必填的環境變數會拒絕啟動；`KOUSHI_PUBLIC_URL` 不是 https 時會警告。
- 開發時仍可用 `python -m koushi.web.app`（Flask 開發伺服器），**正式環境不要用**。
- 要開機自動啟動，見第 5 節的 `-IncludeWeb`。

## 5. 每日排程

以系統管理員身分執行（`-BackupDir` 換成實際的備份位置）：

```powershell
powershell -ExecutionPolicy Bypass -File deploy\register-tasks.ps1 -BackupDir "D:\koushi-backup" -IncludeWeb
```

會在 Windows 工作排程器註冊：

| 工作名稱 | 時間 | 做什麼 |
| --- | --- | --- |
| `KoushiDailyAutomation` | 每天 09:30（`-AutomationTime` 可改） | `deploy\run-automation.ps1`：建主檔、寄補件信與催件、寄附件4、向委員索取資料、讀教授回信 |
| `KoushiDailyBackup` | 每天 22:00（`-BackupTime` 可改） | `deploy\backup_state.py`：備份正式資料（第 6 節） |
| `KoushiWeb` | 開機時（加 `-IncludeWeb` 才註冊） | `deploy\start-web.ps1` |

- **排程時間要晚於「期限設定」頁的每日發送時刻**（預設 9 點）。早於發送時刻時，那一次只會預覽、不寄信。
- 工作以 SYSTEM 帳戶執行，不論有沒有人登入都會跑。
- 註冊後先手動跑一次，確認設定正確：
  ```powershell
  schtasks /Run /TN KoushiDailyAutomation
  ```
  執行紀錄在 `outputs\_logs\automate-日期.log`（保留 90 天）。只想預覽、不寄信時：
  `powershell -ExecutionPolicy Bypass -File deploy\run-automation.ps1 -Preview`
- **失敗時系辦看得到**：每次執行結果寫入 `outputs\_state\automation_status.json`，失敗時系辦工作總覽頂端會出現「每日自動化最近一次執行失敗」警示。程式本身沒能啟動（例如 Python 被移除）時，排程腳本也會補寫一筆失敗紀錄。
- 不會發現的情況：**排程整個沒有執行**（工作被停用、主機關機）時不會留下任何紀錄，總覽只會一直顯示上一次的結果。請系辦留意總覽上「最近一次」的時間是不是今天。

## 6. 備份

`KoushiDailyBackup` 每天把下列資料打包成一個 zip，放到 `-BackupDir`，保留 30 天：

| 資料夾 | 內容 |
| --- | --- |
| `resource\mockdata\submissions\` | 學生填寫（含歷史版本、暫存） |
| `resource\mockdata\data\` | 系辦上傳的附件2、口試委員歷史資料、交通費歷史資料 |
| `outputs\_state\` | 追蹤狀態、寄送紀錄、放行紀錄、委員回填個資、期限設定 |
| `outputs\current\` | 目前的主檔 |

- **備份內含身分證字號、銀行帳號等敏感個資**。目的地必須是只有系辦能存取的位置，建議另一顆磁碟或學校的受控網路磁碟；不可放在專案資料夾內（腳本會拒絕）。
- 手動備份：`.venv\Scripts\python.exe deploy\backup_state.py --dest D:\koushi-backup`
- 還原：先停掉網頁與排程（`schtasks /End /TN KoushiWeb`），把 zip 解壓縮到專案根目錄覆蓋，再重新啟動網頁。

> 注意：正式資料存在名為 `resource\mockdata\` 的資料夾。名稱是開發初期留下的，裡面在正式環境就是真實資料；README 寫的「`resource/mockdata` 永遠只讀」也已不正確（網頁會寫入學生填寫）。改名牽涉多個模組，列為待辦，不在本次處理。

## 7. 上線前檢查清單

1. `deploy\preflight.py` 沒有任何「缺」。
2. 第 3 節的範本測試全部通過；在文件中心實際產一次附件4。
3. 用自己的瀏覽器從**對外網址**（https）打開系統，學生頁、系辦登入都正常。
4. `schtasks /Run /TN KoushiDailyAutomation` 跑一次，日誌沒有錯誤、總覽沒有失敗警示。
5. 手動跑一次備份，確認目的地出現 zip、解得開。
6. 寄一封測試信給自己（例如用自己的學號走一次補件流程），確認 Gmail 寄得出去。

## 8. 本手冊的驗證範圍

以下已在去掉真實資料的專案複本上實測：`preflight.py`、`run-automation.ps1`（成功、Python 執行中失敗兩種情況）、
`backup_state.py`、`start-web.ps1`（waitress 正常回應）。

**未實測**：`register-tasks.ps1`（需要系統管理員權限並會修改主機的排程設定，要在正式主機上執行一次確認）、
真實 Gmail 寄信與 IMAP 收信、HTTPS 反向代理。

## 9. 尚待決定

- **HTTPS 怎麼提供**：waitress 不處理 HTTPS。可以請學校網管在前面加反向代理，或自己在主機上架 IIS／Caddy。這要先問系上網管有什麼既有做法。
- **切換學期後舊學期看不到**：決策文件第八節第 4 條說切換後舊學期「只能查看」，但目前上傳新學期附件2 後，主檔只剩新學期案件，舊學期案件在總覽會被誤標為「附件2 查無」，文件中心也不再列出。詳見上線前待辦清單。
